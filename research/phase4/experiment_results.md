# 第四阶段实际执行结果（主结果：协议 v2）

结论：**当前一维端点保持 Bridge Head 不满足继续 GPU/论文方法开发门槛（NO-GO）**。这是受约束合成组件结论，不是 Plan-R1 真实模型结论，也不是所有可能桥族不可行的证明。

## 真实性与训练

使用原 Vehicle 词表，得到 21 个通过本轮充分动力学证书的基桥。训练/验证/测试 768/192/512 个分离交通场景，测试 broad/boundary 各256；没有真实 checkpoint 输出。12个独立训练模型，每个1,769参数/1,200次 Adam 更新，合计 **14,400 次真实参数更新**，CPU训练合计 9.98s。参数变化、选中 epoch、初始/最终损失逐项见 `results/training_summary.json`；四个 seed 全部保留，没有挑最好 seed。

## 受约束桥存在性

认证系数族的最大空间变化，按21个 token 汇总：min/median/max=0.518/7.853/8.817mm。它是当前充分证书下的族容量，不是所有轨迹的理论上限。共享初态、三个位姿和全程 C2/jerk 约束均检查。

9候选同 token oracle 在512场景中，固定桥 unsafe 而所选桥获得 safe 证书的数量：零 margin **1**（broad 0 / boundary 1）；5mm **2**；2cm **3**；5cm **0**。这些数是**各自 margin 下从不满足到满足**的数量，分母/事件不同，不能解读成“零碰撞救回后还有2cm余量”。`feasibility.csv` 提供每个场景的基桥/最优桥 status。找不到 grid bridge 不证明无解。

## 成本、数值修正与失败

主数据生成 153.64s；训练 9.98s；评价 51.96s。CPU单线程，具体型号/依赖见 environment.json；云主机延迟会抖动。数据集标签轨迹共26,496条（含测试）；所有方法共享同一库。世界模型调用0。在线几何查询按行记录，离线局部最小化/场景构造查询未逐次计数，墙钟包含其代价。

v1使用200Hz标签，被独立区间器发现时间混叠；所有 v1源码/数据/训练日志/指标保留于 `results/diagnostic_v1_sampled_labels/`，**不是主结果**。v2对每个局部极小值 bracket 做连续最小化，并据此构造固定桥附近的边界，网络/限值/种子/训练预算不变。这是发现问题后的数值修正，不是预注册盲测；训练/测试场景仍相互分离，未用测试训练或选 checkpoint。主标签又通过独立区间器抽查，见 label_audit.json；这仍不是所有标签的全局解析证明。

失败案例 `failure_cases.json` 保存 seed17 所有 Bridge 碰撞/unknown；若存在 oracle 可救回场景，`existence_witness.json`/图保存的是**oracle存在性**，不混称学到该能力。第一次JSON导出失败和第二次vectorization广播失败均留日志，修正不涉及原始 Plan-R1。
