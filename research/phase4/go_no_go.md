# Go / no-go：当前 Bridge 方法不进入 GPU/完整模型训练

**NO-GO 针对本轮最低阶、一维、端点保持时间桥作为独立 CCF B/A 方法。** 当前有合成存在性证据，但没有稳定方法优势或真实策略证据，不支持以该 Head 直接开始论文规模训练；本轮不提出 GPU 训练计划。此结论不证明所有高维受约束桥都无用。

## 支持结论的实际证据

1. **严格约束下存在，但余量很小。** 原词表21个通过本轮充分动力学证书的基桥，同一 token 连用两次，初始速度/加速度/曲率完全共享，0/.5/1s 位姿保留、全程 C2。当前系数盒最大位移中位7.853mm、最大8.817mm。512个独立合成测试场景中，九候选 oracle 仅找到一个“固定桥真碰撞→同端点桥获安全证书”实例，来自刻意构造的 boundary 场景；普通 broad 场景零个。
2. **存在性实例不是有实用余量的证据。** `test_136`、原 Vehicle token94：固定桥连续最小 SAT gap约−0.256mm，新桥约+2.494mm；独立区间器分别给 collision/safe。其初速5.038m/s、初始加速度向量[0,0.684]m/s²、初始曲率0.02695m⁻¹，所有变体一致。新桥不满足5mm安全裕量。文件保存完整多项式、box、周车状态/系数，可重新检查。5mm/2cm margin 下另有2/3次跨阈值，不能把它们合并成该碰撞实例具有厘米安全收益；5cm跨阈值零次。
3. **确实学习和独立测试，结果仍不足。** 三种Head×四种子=12个模型，每个1,769参数、1,200步 Adam，14,400次真实更新；训练/验证/测试交通场景分开。原始生成轨迹的四种子平均碰撞率：固定桥37.695%、连续奖励固定primitive选择37.207%、Bridge37.109%。Bridge 相对选择器仅平均0.098个百分点，四种子中三个逐场景碰撞完全相同，另一个只少两例且 paired bootstrap 95%区间包含0。unknown约1.4%，比该微小差值大。所有 broad 场景固定桥/选择器/Bridge 碰撞率相同（24.219%），变化只来自富集的临界场景。
4. **改进没有借助过滤，但也没有独立表示贡献。** Raw Head 每个场景只有一次前向、一个生成结果、零在线安全查询和零拒判。其小收益来自轨迹，而不是外部过滤。另一方面，最低阶端点投影残差 `t³−3t⁴+2t⁵` 与 Bridge 基函数 `2t³(t−.5)(t−1)` 恒等；相同权重的输出/结果逐场景完全相同。当前做法不能仅以“端点保持桥”作为独立技术贡献。
5. **端点松弛会改变问题。** 普通纵向时间残差原始碰撞30.273%，但平均终点误差约0.290m、端点兼容0%。不把它的改善算成同一个 Motion Token 下的安全桥优势。所有生成器使用相同网络、标签可用量与更新预算。

这些碰撞率来自一半随机位置、一半刻意接近碰撞边界的1秒组件场景，绝不是 nuPlan/真实道路碰撞率。原始代码只给端点，不唯一确定桥；当前检查的是明确指定的桥。认证幅值小也可能来自充分界保守、重复token/初态选择、仅纵向重参数化等限制；不能外推“所有 token 都没有可行修正”。

## 已完成的检查与数值失败

官方 fine-tuning 文件81,364,059字节，Drive连接器确实取回；执行器32MiB转存上限阻止本地加载。代码依赖导入成功，meta结构10,072,576参数，真实推理最低资源仍未测得。没有随机预训练替代品。

动力学/初态/端点/跨段连续性有1,702项交叉检查。v1的200Hz标签被区间评估发现混叠，因此保留全部旧代码/结果，v2改为局部连续最小化；抽查864候选对区间器：已确定状态矛盾0、unknown5。修正发生在看过v1评估后，v2复用原场景种子，不是预注册盲测；没有用测试数据训练或选择 checkpoint。数值最小化仍不是所有时间上的全局解析证明。工程失败日志亦保留。

- **物理模型覆盖**：真实初速/加速度/曲率、任意相邻token、控制器重建/跟踪误差、转向变化率和更长时域。当前仅简化无侧滑运动学、恒速刚体周车；没有真实反应、闭环避碰或安全停车/递归可行性。
- **严格最近邻比较**：完整 Plan-R1 仅修复连续奖励、完整 CorrectionPlanner 同标签/同计算比较尚未运行；本轮 selector 是明确标注的组件代理。不能写成已超过论文基线。
- **独立方法能力**：必须先定义超出标准端点投影残差、固定primitive选择和已有生成内安全修正的具体机制，并在匹配标签/参数/候选/计算下证明稳定 RAW 收益与非毫米级余量。扩大网络/候选/标签或仅更换名称不满足此要求。
- **真实推理资源**：checkpoint严格加载兼容性、CPU内存峰值与延迟、真实图规模尚未测量；权重未本地materialize，不能给已验证最低值。只有代码和meta计数不是该证据。

本轮已把可用CPU范围内的受约束验证与实际小模型训练做完。以上缺口是当前立项证据限制；不是需要先购买GPU才能继续的理由。提供真实文件后可以先做CPU推理/控制器审查，仍应沿用相同退出标准。
