# 方法定义、技术重叠与本轮不能证明的事项

本轮承接 PR #3，不重复其文献查新/几何漏检统计。正式来源与阅读范围沿用 [phase3/literature_comparison.md](../phase3/literature_comparison.md) 和 [literature_sources.json](../phase3/literature_sources.json)，本轮没有新增声称已精读的论文。

## 与 CorrectionPlanner 的实质比较

[CorrectionPlanner（ICML 2026，正式全文）](https://proceedings.mlr.press/v306/guo26ae.html) 的 propose–evaluate–correct 根据 collision critic 拒绝 token，并以拒绝 trace 条件化再生成，联合 IL/RL 学习。它已经把安全反馈放入 token 生成，不能将其说成单纯外部检测器。本轮没有其碰撞后端/完整训练复现，也不能断言它漏掉段内碰撞。

本轮桥头在**给定同一个端点 token**下调整段内时间实现，而非拒绝后重采端点。这个控制变量与 CorrectionPlanner 不同，但不自动构成独立贡献：

1. 固定一组可行桥 primitive，仅用同一连续奖励选其中一个，已经可能覆盖效果；本轮同标签 `reward_selector` 就是这一强对照。
2. 端点保持可以是普通残差的线性约束投影。在本轮最低阶一维时间残差中，`r=t³` 加 `a t⁴+b t⁵`，令 `.5/1s` 残差零，解得 `a=−3,b=2`，即 `2t³(t−.5)(t−1)`。因此投影残差和 Bridge **只是系数缩放**；同参数预算下函数集合完全相同。这是直接代数结论，无需用改名网络创造“创新差异”。
3. 即使比离散 token 端点奖励好，也必须排除标签修复、额外候选、端点松弛、外部过滤和初态不一致。本轮对这些因素分别列账；仍没有训练完整 Plan-R1/CorrectionPlanner，不能报告对它们的真实提升。

## 与其他连续安全工具的关系

Bernstein 凸包界、链式法则与固定分离轴运动界是本轮使用的标准工具，不作为新理论。

| 最近邻 | 已有能力 | 当前组件缺少/尚未形成的区别 |
|---|---|---|
| FCL/连续碰撞检测 | 给定运动的连续碰撞查询/保守推进 | 本轮区间 SAT 是专用诊断，不是新 CCD |
| sampled-data CBF | 通过导数/可达界补偿采样间风险 | 本轮无反馈控制不变集，不能继承其安全定理 |
| Predictive safety filter | 备份轨迹、安全终端集、递归可行性 | 本轮的拒判不是该方法，未证明停车安全 |
| REDEFINED/可达性规划 | 保守占据外包络、安全约束优化 | 本轮只对指定桥和恒速障碍给条件证书，无真实跟踪误差包络 |
| SafeDiffuser | 在生成过程中施加安全约束 | “安全进入生成而不是后处理”已被覆盖；本轮必须有更具体且有效的结构贡献 |
| 普通约束轨迹残差/运动 primitive | 端点约束、局部连续修正、候选选择 | 当前一维 Bridge 与投影残差等价，尚无差异化方法证据 |

上述原始论文入口和保证条件详见阶段三比较；这里没有声称穷尽相关研究。尤其“所有现有 Motion Token 安全方法均未研究端点内执行桥”目前**未获验证**。

## 为什么本轮不是联合生成论文原型

本轮确实训练并独立测试了 Bridge Head，但输入是受控 token+合成交通状态；没有接入预训练 hidden states，没有更新 token logits 与桥参数的联合策略，也没有车辆闭环执行。因此能够检验“在严格初态/端点约束下，桥是否存在、可学习、优于简单同标签代理”，不能替代真实联合生成实验。

如果当前 Head 无稳定优势，应停止其 GPU 扩展。未来即便改成高维横纵向 bridge，也必须先过同标签投影残差与固定 primitive 的门槛；仅增加维度、网络或标签不足以成为 CCF 论文贡献。本轮不提出完整 GPU 训练计划。
